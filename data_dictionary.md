Kigaliclean - Data Dictionary 

 1. COUNTRY
Purpose: List of countries where bottles are scanned. One row per country, so we don't repeat country names.
Normalization:In 3NF. Country name depends only on country_code.
Keys: country_code is PK, natural key. country_name is UNIQUE.

| Column | Data type | Null? | Constraint | Why / description |
|---|---|---|---|---|
| country_code | VARCHAR2(5) | No | PK | Short code, e.g. MW, MZ, UG |
| country_name | VARCHAR2(100) | No | UNIQUE, NOT NULL | Full name, e.g. Malawi |
| region | VARCHAR2(100) | Yes | - | Region, can be empty if unknown |

## 2. MANUFACTURER
**Purpose:** Company that makes the drink, e.g. Oyoma General.
**Normalization:** In 3NF. Manufacturer name depends only on manufacturer_id. Country moved to COUNTRY.
**Keys:** manufacturer_id is PK, surrogate key because names can repeat. manufacturer_name is UNIQUE.

| Column | Data type | Null? | Constraint | Why / description |
|---|---|---|---|---|
| manufacturer_id | NUMBER(10) | No | PK | ID, generated by system |
| manufacturer_name | VARCHAR2(100) | No | UNIQUE, NOT NULL | Company name, e.g. Oyoma General |
| manufacturer_country | VARCHAR2(5) | Yes | FK -> COUNTRY | Country code of manufacturer. Can be NULL if unknown |

## 3. BRAND
**Purpose:** Brand name, e.g. Kabisa. One brand belongs to one manufacturer.
**Normalization:** In 3NF. Brand name depends only on brand_id.
**Keys:** brand_id is PK, surrogate key. brand_name is UNIQUE.

| Column | Data type | Null? | Constraint | Why / description |
|---|---|---|---|---|
| brand_id | NUMBER(10) | No | PK | ID, generated by system |
| brand_name | VARCHAR2(100) | No | UNIQUE, NOT NULL | Brand name, e.g. Kabisa |
| manufacturer_id | NUMBER(10) | No | FK -> MANUFACTURER, NOT NULL | Which manufacturer owns this brand. Must have a manufacturer |

## 4. PRODUCT
**Purpose:** One product, e.g. Kumbucha Alcoholic Drink, barcode 1234003331.
**Normalization:** In 3NF. Product label and weight depend only on barcode. Brand moved to BRAND.
**Keys:** product_barcode is PK, natural key from real data. 

| Column | Data type | Null? | Constraint | Why / description |
|---|---|---|---|---|
| product_barcode | VARCHAR2(50) | No | PK | Real barcode from file, e.g. 1234003331. Text so Excel does not change it to 2.15E+09 |
| product_label | VARCHAR2(200) | No | NOT NULL | Name on bottle, e.g. Kumbucha Alcoholic Drink |
| product_size | VARCHAR2(50) | Yes | - | Size, e.g. 500ml. Can be empty |
| brand_id | NUMBER(10) | No | FK -> BRAND, NOT NULL | Which brand this product belongs to |
| bottle_weight | NUMBER(10,2) | Yes | CHECK > 0 | Weight in grams. Must be more than 0 if given |

## 5. SCAN
**Purpose:** One scan event: how many bottles of one product were found in one country.
**Normalization:** In 3NF. Bottle count depends on the full scan (product + country), not on product alone.
**Keys:** scan_id is PK, surrogate key. (product_barcode + scan_country) is also UNIQUE - one row per product per country.

| Column | Data type | Null? | Constraint | Why / description |
|---|---|---|---|---|
| scan_id | NUMBER(10) | No | PK | ID, generated by system |
| product_barcode | VARCHAR2(50) | No | FK -> PRODUCT, NOT NULL | Which product was scanned |
| scan_country | VARCHAR2(5) | No | FK -> COUNTRY, NOT NULL | Where it was scanned |
| bottle_count | NUMBER(10) | No | CHECK > 0, NOT NULL | How many bottles, e.g. 376. Must be more than 0 |
| data_url | VARCHAR2(500) | Yes | - | Link to raw data. Can be empty |

## 6. Foreign-Key Decision Table

| Foreign key name | Child table | Parent table | Rule chosen | Why this rule |
|---|---|---|---|---|
| fk_manufacturer_country | MANUFACTURER | COUNTRY | ON DELETE SET NULL | If country is deleted, manufacturer stays but country becomes NULL |
| fk_brand_manufacturer | BRAND | MANUFACTURER | NO ACTION | Cannot delete manufacturer if it still has brands. Protects history |
| fk_product_brand | PRODUCT | BRAND | NO ACTION | Cannot delete brand if it still has products |
| fk_scan_product | SCAN | PRODUCT | ON DELETE CASCADE | A scan cannot exist without its product. Delete product = delete its scans |
| fk_scan_country | SCAN | COUNTRY | NO ACTION | Cannot delete country if it still has scans |

**How I handle key updates in Oracle:** Oracle does not support ON UPDATE CASCADE. So I never update a PK if it has child rows. If I must change a code, I insert a new parent row, update child rows to the new code in one transaction, then delete the old parent. This keeps FKs valid.
